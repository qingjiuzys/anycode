## 调研后的定位结论

「AI 时代的操作系统」和「AI 界的 SAP」都指向同一野心，但**对外主口号不要用后者**。

| 候选口号 | 判断 |
|---|---|
| AI 界的 SAP | **不宜作主标**。SAP 自己已在 2026 把 ERP 说成 Autonomous Enterprise 的操作系统；金蝶灵基也在卖「企业 AI 操作系统」。对 CIO 来说，「我们是某某的 SAP」等于暗示要换交易系统，项目周期长、风险高，且我们并不做财务/HR/供应链账本。 |
| AI 时代的操作系统 | **可用，但必须加限定**。操作系统这个词已被微软、Salesforce、ServiceNow、金蝶同时占用。单独说「OS」太空。 |
| 企业 AI 原生治理底座 | **主定位**。准确：管的是 Agent 怎么上岗、用哪份知识、数据落在哪、谁审批、如何审计。 |
| 工作操作系统 / 控制平面 | **主比喻**。SAP/ERP 是交易操作系统（System of Record，记录发生了什么）；我们是工作操作系统（System of Agency，决定智能体能做什么）。 |

一句话：

> **模型会推理，底座来治理。**  
> 我们不做下一套 ERP，而做 ERP 旁边、能让智能体在内网上岗的控制平面。

行业对得上的语言（2026）：

- SAP North Star：*the model reasons, the harness governs*（模型推理，套件治理）
- 金蝶灵基：灵基不是替代 ERP，而是在经营系统之上增加 AI 原生能力
- 企业 Agent 实践：本地 Agent 越自由，越需要授权、审计、知识边界

我们的差异不是「更会聊天」，而是四件事同时成立：**内网、K8s、S3、知识库**，再叠 anyCode 执行 + 818Cloud 控制平面 + Mail 通道。

## 四件套怎么讲

| 平面 | 产品 | 对企业的一句话 |
|---|---|---|
| 执行 | **anyCode** | 默认在本地工作的企业级智能体：工具与审批不出机器 |
| 控制 | **818Cloud** | 账户、模型网关、K8s 交付与计费的控制平面 |
| 通道 | **Mail** | 邮件是企业最大的非结构化入口：进知识库、可检索、附件落 S3 |
| 记忆 | **知识库（灵知）** | 制度 / 项目 / 客户材料收进来，问一句能回到原文 |
