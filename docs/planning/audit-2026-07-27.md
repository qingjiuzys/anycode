## 2. 结构评估

**骨架是健康的。** 组合根唯一(bootstrap::initialize_runtime)、编排权威唯一(AgentRuntime，双编排器共享 compile_for_prompt)、评测路径与生产路径同构(execute_task)。ADR 000/002/010 三条架构红线目前都守住了。

**规模风险集中在三处：**
1. `crates/agent/src/runtime/`(38 个文件)——execute_turn.rs 仍是最大单文件；Q8 余项（weak-local 恢复双实现）未合并。
2. `crates/dashboard/`(217 个 API handler)——路由面大，handler 分组尚可但缺少统一输入校验层。
3. 评测基建分布在 `test/runner`、`scripts/`、`scripts/office`、`scripts/lib` 四处，去重后仍偏散。

## 3. 风险清单（按严重度）

### 高
- **LLM 网关单点**:anthropic/openai 客户端已加配额快速失败与过载重试，但 **所有实时路径共用全局 chat 模型**；网关故障 = 全功能停摆。failover 存在但只配置单跳。
- **eval 覆盖率假象**:smoke 的 P0/P1 覆盖 100%,但 **hidden split 四臂评测从未跑过**(M4 promotion gate 未通过）。Experience+Skill 按文档仍属 lab/opt-in，不能对用户宣称质量提升。

### 中
- **execute_task / execute_turn 残余双实现**(weak-local 恢复、消息注入策略）——语义已收敛但代码仍两份，后续改动容易漏一边。
- **E2EE 同步未端到端验证**:memory-sync 版本向量守卫有单测，但 server(account-service）与 client 的联合 round-trip 没有集成测试。
- **desktop 对 127.0.0.1:43180 的硬依赖**：端口被占/防火墙提示即启动失败。本轮已拒绝误杀非 anycode 进程，但根因（HTTP loopback 作为唯一传输）未解。
- **37 处进程级 `env::set_var`**：多为兼容遗留（SESSION_ENV 等），并发化时是会话串扰隐患（task-local 已覆盖主路径）。

### 低
- `test/runner` 与 `scripts/` 的 python 无 CI lint（仅 AST parse 抽查）。
- 8 处 TODO/FIXME、15 处 runtime unwrap（均在已审计的非热路径）。
- account-portal 与 account-service 是 workspace 外 crate，版本联动靠手工。

## 5. 下一步迭代计划（建议按序）

1. **M4 promotion 闭环**（评测证据）:hidden split 四臂 + 视觉盲评，输出 promote/不 promote 的定论；不达则默认回退 Skill-only。（风险最高项）
2. **execute_turn / execute_task 最终收敛**：统一为单编排实现 + turn/task 两个薄壳；顺带清理 weak-local 双实现与消息注入字符串耦合。
3. **桌面传输去 loopback 化**:Tauri custom protocol( 或 Unix socket）承载 dashboard UI；消灭端口冲突与防火墙提示类故障。
4. **E2EE 联合 round-trip 集成测试** + recovery phrase 落地（当前字段是空的）。
5. **failover 多跳配置**与网关健康探测(cloud_session 已有雏形），消除单点。
6. dashboard handler 输入校验统一层（217 个端点的参数校验目前散在各处）。
